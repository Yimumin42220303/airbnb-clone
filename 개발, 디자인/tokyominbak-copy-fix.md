# 도쿄민박 문구·정보구조 모순 제거 작업 지시서

## 목적

게스트가 사이트를 자세히 살펴봤을 때 느낄 수 있는 모순점을 제거한다.
문구·표시·UI 정보구조 중심의 수정이며, **기능 코드(예약·결제·Beds24·webhook·cron)는 절대 수정하지 않는다.**

---

## 절대 금지 사항 (작업 전 반드시 확인)

- `prisma/schema.prisma` 수정 금지 → DB 스키마 변경 없음
- DB 마이그레이션(`npm run db:migrate`) 실행 금지
- `lib/portone.ts`, `lib/beds24.ts`, `app/api/payment/`, `app/api/bookings/` 등 결제·예약 로직 수정 금지
- webhook, cron, 예약 상태 처리 코드 수정 금지
- 환경변수(`.env`) 수정 금지
- 기존 데이터를 변경하는 API 호출 금지

---

## 사전 조사 (수정 전 반드시 실행)

작업 시작 전에 아래 항목을 코드에서 직접 확인하고, 결과를 바탕으로 수정한다.

### 1. 승인형 예약 결제 타이밍 파악

`app/api/bookings/`, `lib/bookings.ts`, `app/booking/` 를 읽어서 아래를 확인한다:
- 승인형 숙소의 결제가 **요청 전** 발생하는지, **승인 후** 발생하는지
- 확인 결과에 따라 `/agreement` 문구를 실제 플로우에 맞게 작성한다 (아래 9번 참고)

### 2. 한국어 호스트 배지 데이터 구조 파악

`prisma/schema.prisma`, `app/listing/[id]/` 를 읽어서 확인:
- 호스트 또는 숙소에 "한국어 가능" 여부를 저장하는 필드가 있는지
- 없으면: 배지를 일괄 "도쿄민박 한국어 안내 가능"으로 교체하고 조건 분기는 만들지 않는다

### 3. 자동 생성 추천 문구 템플릿 위치 파악

숙소 상세(`app/listing/[id]/`)에서 인원·추천대상 문구를 생성하는 템플릿을 찾는다.
최대 인원과 추천 인원 문구가 충돌하는 경우 조건을 수정한다.

## Phase 1 — 게스트가 즉시 체감하는 모순 (최우선)

### 1-1. 숙소 상세 "호스팅" 문구 제거

`app/listing/[id]/` 에서:
- "도쿄민박 님이 호스팅" 또는 이와 유사한 표현 제거
- 섹션명을 **"숙소 운영 및 한국어 안내"** 로 교체
- 내용 교체:

```
한국어 고객지원: 도쿄민박 고객지원팀
숙소 운영/현장 관리: 현지 숙소 운영자 또는 일본 현지 파트너
```

- 예약 카드 근처 문구 추가:

```
한국어 예약 안내 포함
이 숙소는 도쿄민박 고객지원팀이 예약 전 문의, 체크인 안내, 숙박 중 문제 접수를 한국어로 도와드립니다.
숙박 제공과 현장 관리는 숙소 운영자 또는 일본 현지 파트너가 담당합니다.
```

- 체크인 안내 문구 교체:

```
예약 확정 후, 도쿄민박 고객지원팀이 숙소 운영자 또는 일본 현지 파트너로부터 확인한 체크인 안내를 한국어로 전달합니다.
숙소별 규칙이나 현장 확인이 필요한 내용은 숙소 운영자 또는 현지 파트너와 확인 후 안내드립니다.
```

- 자동확정 툴팁 문구 교체:

```
결제 완료 시 원칙적으로 예약이 즉시 확정됩니다.
단, 시스템 오류나 중복 예약 등 예외 상황이 확인되는 경우 전액 환불 후 안내드릴 수 있습니다.
```

### 1-2. 한국어 호스트 배지 수정

- "한국어 가능 호스트" → 실제 호스트가 한국어 가능한 데이터가 있는 경우에만 유지
- 데이터 없는 경우: **"도쿄민박 한국어 안내 가능"** 또는 **"한국어 고객지원 가능"** 으로 일괄 교체

### 1-3. /recommend 문구 수정

`app/recommend/` 에서:

- 제목: **"내 조건에 맞는 도쿄 숙소 3곳 추천받기"**
- 서브카피:

```
일정·인원·희망 지역을 입력하면 조건에 맞는 후보 숙소 3곳을 먼저 확인할 수 있습니다.
최종 요금과 예약 가능 여부는 한국인 스태프가 숙소 운영자 또는 일본 현지 파트너와 확인 후 안내합니다.
```

- 결과 상단 안내 문구 추가:

```
추천 결과는 입력 조건을 바탕으로 한 후보 숙소입니다.
최종 요금, 예약 가능 여부, 체크인 조건, 취소·환불 조건은 상담 또는 예약 전 확인이 필요합니다.
```

- 추천 결과 카드에 표시할 항목:
  - 추천 이유
  - 주의할 점
  - 최종 확인 필요
  - 한국어 안내 가능
  - 상세 보기
  - 이 숙소로 상담하기

### 1-4. /policy "법무 검토 TODO" 삭제

`app/policy/` (또는 해당 경로) 에서 공개 노출된 "법무 검토 TODO" 문구를 찾아 아래로 교체:

```
숙소 추천 상담을 요청하는 경우, 입력한 일정, 인원, 희망 위치, 중요 조건, 예산, 추천 숙소 정보,
상담 식별번호 등은 추천 결과 제공, 상담 연결 및 상담 이력 관리를 위해 처리될 수 있습니다.
추천 결과 생성 과정에서 일부 조건이 AI API로 처리될 수 있으며,
상담 진행 시 입력 조건과 추천 결과가 도쿄민박 고객지원팀에 전달될 수 있습니다.
```

### 2-4. /agreement 수정

**사전 조사에서 확인한 실제 결제 타이밍을 기준으로** 아래 중 하나를 적용한다:

**Case A — 승인 후 결제인 경우:**
```
승인형 숙소는 회원이 예약 요청을 제출한 후 숙소 운영자의 가능 여부 확인을 거칩니다.
숙소 운영자가 요청을 승인하면 결제 링크가 발송되며,
회원이 결제를 완료한 시점에 예약이 확정됩니다.
승인되지 않은 예약 요청에는 결제가 발생하지 않습니다.
```

**Case B — 결제 후 승인 대기인 경우:**
```
승인형 숙소는 결제 완료 후 숙소 운영자의 최종 확인을 거쳐 예약이 확정됩니다.
운영자가 승인하지 않는 경우 결제 금액은 전액 환불됩니다.
```

`/trust` 및 예약 화면의 동일 안내 문구와 반드시 일치시킨다.

## Phase 4 — 추가 항목

### 4-1. /recommend 상담 연결 동의 문구

상담 연결 버튼 근처에 아래 문구 추가:
```
상담을 진행하면 입력하신 조건과 추천 결과가 도쿄민박 고객지원팀에 전달됩니다.
```

가능하면 체크박스 추가:
```
입력한 조건과 추천 결과를 도쿄민박 고객지원팀에 전달하여 상담을 진행하는 데 동의합니다.
```

### 4-2. 숙소 상세 운영 정보 섹션 (데이터 있을 때만 표시)

DB에 운영 유형·허가번호 데이터가 없으면 섹션 자체를 표시하지 않는다.
데이터가 있는 경우에만 "숙소 운영 정보" 섹션을 추가하고 아래 구조로 표시:

```
운영 유형: 住宅宿泊事業 / 旅館業 / 特区民泊 / 기타
허가·신고번호: [번호] 또는 "예약 전 문의 가능"
숙소 운영자: 현지 숙소 운영자
한국어 안내: 도쿄민박 고객지원팀
```

### 4-3. 자동 생성 추천 문구 조건 수정

숙소 상세에서 인원·추천대상 문구를 자동 생성하는 템플릿을 찾아:
- 최대 인원이 2명인 경우 "2~3인 추천" 같은 문구가 생성되지 않도록 조건을 수정한다
- 추천 인원 상한이 숙소 최대 인원을 초과하지 않게 한다

### 4-4. 호스트 모집 페이지 수정

`app/lp/host/` 또는 유사 경로에서 셀프 운용 플랜 설명 교체:

```
셀프 운용 플랜은 호스트가 숙소 운영과 현장 대응을 직접 수행하는 플랜입니다.
단, 도쿄민박을 통해 예약한 한국인 게스트의 기본 문의와 예약 전후 안내는
도쿄민박 고객지원 창구를 통해 접수될 수 있습니다.
현장 조치와 숙소 운영 판단은 호스트가 담당합니다.
```
