# 체크아웃 게스트 평점·리뷰 유도 기획

체크아웃한 게스트가 숙소에 평점과 리뷰를 남기도록 하는 **프로덕트·UX/UI 기획** 문서입니다.

---

## 1. 목표와 성공 지표

| 목표 | 설명 |
|------|------|
| **리뷰 수 증가** | 숙소당 리뷰 개수 증가 → 신규 게스트의 신뢰·전환 향상 |
| **적시 유도** | 체크아웃 직후 기억이 생생할 때 리뷰 작성률 극대화 |
| **답변 놓침 방지** | 호스트가 “리뷰 요청”을 따로 하지 않아도 시스템이 적절한 시점에 요청 |

**성공 지표 예시**
- 체크아웃 완료 대비 리뷰 작성률 (목표: e.g. 15~25%)
- 리뷰 유도 채널별 전환 (예약 상세 버튼 vs 이메일 링크)
- 평균 평점·리뷰 글자 수 (품질 간이 지표)

---

## 2. 현재 구조 요약

- **리뷰 모델**: `Review` — `listingId`, `userId`, `rating`(1~5), `body`, `authorDisplayName`, 이미지. **bookingId 없음**.
- **작성 권한**: `canUserReview` — “해당 숙소 **확정·체크아웃 경과** 예약이 있는 게스트”만 작성 가능. **숙소당 1인 1리뷰** (관리자 제외).
- **유도 경로**:  
  - **내 예약** → 과거 예약 상세 → `canReview`(확정 + 체크아웃 지남)일 때 **「리뷰 작성」** 버튼 → `/listing/[id]#review` 로 이동해 리뷰 섹션에서 작성.
- **부족한 점**  
  - 체크아웃 후 **자동 리마인더(이메일/알림)** 없음.  
  - “이 예약에 대한 리뷰”가 아니라 “숙소 페이지로 가서 쓰기”라서, **어떤 숙박**에 대한 리뷰인지 맥락이 약함.  
  - 이미 리뷰를 썼는지 예약 상세에서 안 보여서, 버튼을 눌러야 “이미 작성함”을 알 수 있음.

---

## 3. 설계 원칙

1. **체크아웃 이후에만** 리뷰 요청 (이미 로직 상 반영됨).
2. **부담 최소화**: 평점(필수) + 짧은 글(선택) + 사진(선택). 단계별로 한 화면에 모아서 빠르게 끝낼 수 있게.
3. **맥락 명확**: “OO 숙소, N월 N일 체크아웃한 예약”에 대한 리뷰라는 걸 UI/문구로 드러내기.
4. **반복 게스트**: 현재는 “숙소당 1인 1리뷰”. 같은 숙소 재숙박 시 리뷰 한 번 더 쓰게 하려면 “예약당 1리뷰”로 확장 검토 (3.1절).

---

## 4. 데이터 설계 제안

### 4.1 리뷰 단위: “숙소당 1인 1리뷰” vs “예약당 1리뷰”

| 방식 | 장점 | 단점 |
|------|------|------|
| **현재: 숙소당 1인 1리뷰** | 구현 변경 없음, 중복 리뷰 방지 | 같은 숙소 재숙박 시 리뷰 불가 |
| **예약당 1리뷰 (bookingId 연결)** | 재숙박 시에도 매번 리뷰 가능, “N월 숙박 리뷰” 표시 가능 | 스키마 변경·마이그레이션, 목록/상세 노출 규칙 필요 |

**권장 (단계적)**  
- **1단계**: 현재처럼 “숙소당 1인 1리뷰” 유지. **유도 채널·타이밍·문구·UI**만 개선해서 작성률 끌어올리기.  
- **2단계**: 리뷰 풀을 더 쌓이고 싶을 때 `Review.bookingId`(optional) 도입해 “이번 예약에 대한 리뷰”로 연결하고, 재숙박 게스트도 리뷰 작성 가능하게.

---

## 5. 유도 채널·타이밍 설계

### 5.1 언제 리뷰를 요청할지

| 시점 | 설명 | 우선순위 |
|------|------|----------|
| **체크아웃 당일 또는 다음날** | 기억이 선할 때, 이메일/알림으로 한 번 요청 | 높음 |
| **내 예약 목록·상세** | 과거 예약 들어갈 때 “리뷰 남기기” 노출 | 높음 (이미 버튼 있음, 강화) |
| **결제 완료/체크인 안내 이메일** | “체크아웃 후 리뷰 부탁드려요” 한 줄 안내 | 중간 |

### 5.2 채널별 UX

1. **이메일 (체크아웃 D+1)**  
   - 제목 예: `[도쿄민박] OO 숙소는 어떠셨나요? 리뷰를 남겨주세요`  
   - 본문: 숙소명, 체크인·체크아웃, 짧은 감사 문구 + **리뷰 작성 버튼** (링크: `/listing/[id]#review` 또는 전용 `/booking/[id]/review`).  
   - 한 번만 발송 (이미 리뷰 쓴 경우 제외).

2. **앱/웹 알림**  
   - “OO 숙소 숙박이 끝났어요. 경험을 리뷰로 남겨주실 수 있나요?” → 클릭 시 리뷰 작성 화면.

3. **내 예약 상세 (기존 강화)**  
   - `canReview && !hasReviewed` 일 때: **리뷰 작성** 버튼을 더 눈에 띄게 (예: primary 스타일, 아이콘).  
   - `hasReviewed` 일 때: “리뷰를 작성해 주셨습니다. 감사합니다.” 문구 + (선택) 작성한 리뷰로 가는 링크.  
   - API: `GET /api/bookings/[id]` 응답에 `hasReviewed: boolean` 포함 (해당 listing+user 기준으로 기존 리뷰 존재 여부).

---

## 6. UI/UX 상세

### 6.1 리뷰 작성 플로우 (현재 유지 + 개선)

**옵션 A (최소 변경)**  
- 유지: “리뷰 작성” 클릭 → `/listing/[id]#review` → 기존 `ReviewForm`.  
- 개선:  
  - 예약 상세에서 `hasReviewed` 반영해 버튼/문구 전환.  
  - 리뷰 섹션 상단 문구: “체크아웃하신 숙소에 대한 리뷰를 남겨주세요.”

**옵션 B (예약 컨텍스트 강화)**  
- 새 경로: `/booking/[id]/review` (해당 예약이 본인 것인지, `canReview` 조건 검사).  
- 같은 화면에 **숙소 카드(썸네일·이름·체크인/아웃)** 한 줄로 노출 → “이 숙박에 대한 리뷰” 느낌.  
- 폼은 기존과 동일: 별점(필수) + 본문(선택) + 사진(선택). 제출 시 기존 `POST /api/listings/[id]/reviews` 호출 (필요 시 `bookingId` 쿼리/바디로 전달해 저장).

### 6.2 작성 폼 (현재 유지, 문구만 정리)

- **필수**: 별 1~5 (한 번에 선택, 터치/클릭 친화적).  
- **선택**:  
  - 리뷰 글 (placeholder 예: “숙소와 호스트에 대한 경험을 자유롭게 적어주세요.”).  
  - 사진 최대 N장 (이미 구현된 경우 유지).  
- 제출 전: “다른 게스트에게 도움이 됩니다.” 같은 짧은 동기 부여 문구.  
- 제출 후: “리뷰를 남겨주셔서 감사합니다.” 토스트/메시지 + (선택) 내 예약으로 돌아가기 링크.

### 6.3 표시 (숙소 상세)

- 기존대로: 평균 평점 + 리뷰 목록 + 정렬.  
- “예약당 1리뷰” 도입 시: 각 리뷰에 “N월 숙박” 등 표시 가능 (선택).

---

## 7. 문구·다국어

- **한국어**: “리뷰 작성”, “숙소는 어떠셨나요? 리뷰를 남겨주세요”, “이미 리뷰를 작성해 주셨습니다. 감사합니다.”  
- **일본어**: `host-i18n` 등 기존 번역 키와 패턴 맞춰 추가 (예: `review.writeReview`, `review.inviteAfterCheckout`, `review.thankYouAlready`).

---

## 8. 구현 단계 제안

| 단계 | 내용 | 비고 |
|------|------|------|
| **Phase 1** | 예약 상세에 `hasReviewed` 연동 + 리뷰 버튼/감사 문구 전환 | API 확장 + 프론트 수정 |
| **Phase 2** | 체크아웃 D+1 “리뷰 요청” 이메일 (예: cron + 이메일 템플릿) | 이미 리뷰 쓴 유저 제외 |
| **Phase 3** | (선택) 인앱 알림 “리뷰 남겨주세요” | notifications + 링크 |
| **Phase 4** | (선택) `/booking/[id]/review` 전용 페이지로 “이번 숙박” 맥락 강화 | 옵션 B |
| **Phase 5** | (선택) `Review.bookingId` 도입해 예약당 1리뷰·재숙박 리뷰 허용 | 스키마·마이그레이션 |

---

## 9. 요약

- **지금 당장**: “체크아웃한 게스트에게 평점·리뷰 남기게” 하려면 **유도 채널과 타이밍**이 핵심.  
- **데이터**: 1단계는 **숙소당 1인 1리뷰** 유지, **hasReviewed**만 예약 상세에 반영.  
- **UX**: 예약 상세에서 리뷰 버튼/감사 문구 명확히 + **체크아웃 다음날 이메일** 한 통으로 작성률을 끌어올리는 구성을 권장합니다.

이 기획안을 기준으로 Phase 1부터 순서대로 구현하면, 체크아웃한 게스트가 평점·리뷰를 남기기 쉬운 플로우를 만들 수 있습니다.
