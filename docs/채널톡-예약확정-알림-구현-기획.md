# 예약·결제 확정 후 채널톡 알림 — 구현 기획 (다음 단계)

채널톡 활용 가이드 **4-2**를 구현하기 위한 구체 작업 순서와 파일·API 정리.

---

## 구현 완료 요약 (체크리스트)

| 단계 | 내용 | 상태 | 비고 |
|------|------|------|------|
| **1** | 채널톡 부트 시 `memberId` 설정 | ✅ | `ChannelTalk.tsx` — 세션 로드 후 boot, 로그인 시 `session.userId`를 memberId로 전달 |
| **2** | 환경 변수 | ✅ | `.env.example`에 `CHANNEL_ACCESS_KEY`, `CHANNEL_ACCESS_SECRET` 주석 추가 |
| **3** | 채널 Open API 유틸 | ✅ | `src/lib/channel-api.ts` — User 조회(memberId) → UserChat 생성 → 메시지 발송. API 키 없으면 무시 |
| **4** | 결제 확정 시 채널톡 호출 | ✅ | `POST /api/payments/verify`, `POST /api/payments/mock-verify` 성공 후 `sendChannelTalkNotification(userId, 메시지)` 호출. 실패해도 200·conversationId 유지 |

**발송 문구**: `"예약이 확정되었습니다. 메시지창에서 자세한 내용을 확인하세요."`

**운영 시 할 일**: [채널톡-API키-설정.md](./채널톡-API키-설정.md) 참고. 요약하면, 채널톡 데스크 → **설정** → **API Key 관리**에서 Access Key·Access Secret 발급 후, `CHANNEL_ACCESS_KEY` / `CHANNEL_ACCESS_SECRET`을 로컬 `.env`와 Vercel 환경 변수에 넣으면 결제 확정 시 알림이 발송됩니다. 미설정 시 알림만 건너뛰고 결제·리다이렉트는 정상 동작합니다.

---

## 1. 목표

- 결제 확정(또는 모의 결제 확정) 후 **메시지창(/messages/[id])으로 리다이렉트**되는 시점에, **채널톡으로도 봇 메시지**를 한 통 보낸다.
- 사용자가 채널톡 위젯을 열면 "예약이 확정되었습니다. 메시지에서 자세한 내용을 확인하세요." 같은 문구가 보이도록 한다.

---

## 2. 전제 조건

- **memberId 연동**: 채널톡 부트 시 우리 서비스의 **사용자 ID**를 `memberId`로 넘겨 두어야, 서버에서 "이 사용자의 채널톡 채팅"을 식별할 수 있다.
- **API 키**: 채널톡 데스크에서 발급한 **Access Key / Access Secret**을 서버 환경 변수로만 보관하고, 클라이언트에 노출하지 않는다.

---

## 3. 구현 작업 목록

### 3-1. 채널톡 부트 시 memberId 설정 (클라이언트)

| 항목 | 내용 |
|------|------|
| **파일** | `src/components/channel/ChannelTalk.tsx` |
| **작업** | `useSession()`으로 로그인 사용자 정보를 읽고, `session?.user`가 있을 때 boot 옵션에 `memberId` 추가. |
| **memberId 값** | 우리 DB 사용자 ID. NextAuth 세션에 `userId`가 있으면 그대로 사용 (`(session as { userId?: string }).userId` 또는 `session.user.id` 등 프로젝트에서 사용하는 필드). |
| **주의** | 채널톡 문서에 따르면 memberId는 "회사가 사용하는 사용자 식별자"이므로, 우리 User 테이블의 `id`(cuid 등)를 문자열로 넣으면 됨. |

→ 로그인 사용자가 채널톡을 한 번이라도 연 동일 사용자가, 서버 API 호출 시 `memberId`로 조회 가능해짐.

### 3-2. 환경 변수 (채널톡 API 키)

| 항목 | 내용 |
|------|------|
| **변수명** | `CHANNEL_ACCESS_KEY`, `CHANNEL_ACCESS_SECRET` (또는 `CHANNEL_API_ACCESS_KEY` 등 팀 규칙에 맞게). |
| **설정** | 채널톡 데스크 → 설정 → 보안 및 개발 → API에서 발급. 서버(로컬 `.env`, Vercel Environment Variables)에만 등록. |
| **문서** | `.env.example`에 주석으로 예시 추가 (실제 값은 비워 둠). |

---

### 3-3. 채널톡 Open API 호출 유틸 (서버)

| 항목 | 내용 |
|------|------|
| **파일** | `src/lib/channel-api.ts` (신규) 또는 `src/lib/channel.ts`. |
| **역할** | 1) memberId로 채널톡 User 조회, 2) 해당 User의 UserChat 조회 또는 생성, 3) 해당 UserChat에 봇 메시지 발송. |
| **API 흐름** | 1. `GET https://api.channel.io/open/v5/users/@{memberId}` (채널톡 문서: @ 접두사) → User 객체 획득. 2. 해당 User의 userChat 목록 조회 또는 "기본" 채팅 사용 (채널톡 문서의 List UserChats / Create UserChat 참고). 3. `POST https://api.channel.io/open/v5/user-chats/{userChatId}/messages` 로 메시지 본문 전송. |
| **인증** | 채널톡 Open API는 보통 Access Key + Secret으로 인증 (문서 확인 후 헤더에 포함). |
| **에러 처리** | User가 없음(404) → 해당 사용자가 채널톡을 한 번도 연 적 없을 수 있음. 이 경우 알림 생략하고 로그만 남기고 정상 응답 유지. 메시지 발송 실패 시에도 결제 확정 플로우는 실패하지 않도록 try/catch로 감싼다. |

→ 이 유틸을 "memberId + 메시지 텍스트"를 인자로 받는 함수 하나로 두고, 결제 확정 처리에서만 호출하도록 한다.

---

### 3-4. 결제 확정 시점에서 채널톡 알림 호출 (서버)

| 항목 | 내용 |
|------|------|
| **호출 위치** | `src/app/api/payments/verify/route.ts` — 결제 검증 성공 후 `onPaymentVerified(bookingId)` 호출이 끝난 직후, `return NextResponse.json(...)` 직전. 동일한 "결제 확정" 플로우를 타는 `src/app/api/payments/mock-verify/route.ts`에도 동일 로직 추가. |
| **전달 정보** | 이미 세션에서 `userId`(우리 DB 사용자 ID)를 가지고 있음. 이 값을 memberId로 채널톡 유틸에 전달. 메시지 문구는 상수 또는 번역 키로 "예약이 확정되었습니다. 메시지창에서 자세한 내용을 확인하세요." 등. |
| **동작** | `sendChannelTalkNotification(userId: string, message: string)` 같은 함수를 호출. 실패해도 200 + conversationId 응답은 그대로 반환(알림 실패가 결제 완료를 막지 않도록). |

### 3-5. (선택) 즉시 예약 확정 시 채널톡 알림

| 항목 | 내용 |
|------|------|
| **상황** | 결제 없이 "즉시 예약"으로 예약만 생성되는 플로우가 있다면, 그 시점에도 채널톡 알림을 보내고 싶을 수 있음. |
| **위치** | 예약 생성·확정을 처리하는 API (예: `src/app/api/bookings/route.ts` 등)에서 확정 시점을 찾아, 위와 동일한 `sendChannelTalkNotification(booking.userId, ...)` 호출을 추가. |
| **우선순위** | 1차는 "결제 확정 후"만 구현하고, 필요 시 즉시 예약 확정 알림을 2차로 추가. |

## 4. 구현 순서 제안

1. **1단계**: 채널톡 부트에 `memberId` 추가 (`ChannelTalk.tsx`) + `.env.example`에 채널톡 API 키 항목 추가.
2. **2단계**: 채널톡 Open API 인증·User 조회·UserChat 조회/생성·메시지 발송을 담당하는 서버 유틸 함수 구현 (`src/lib/channel-api.ts` 또는 `channel.ts`).
3. **3단계**: `POST /api/payments/verify`와 `POST /api/payments/mock-verify`에서 결제 확정 처리 성공 후, 위 유틸을 호출해 봇 메시지 발송 (실패 시 로그만, 응답은 기존대로).
4. **4단계**: (선택) 즉시 예약 확정 시 알림 추가.

---

## 5. 채널톡 API 참고

- 사용자 조회 (memberId): `GET https://api.channel.io/open/v5/users/@{memberId}`
- UserChat 생성: `POST https://api.channel.io/open/v5/users/{userId}/user-chats`
- 메시지 발송: `POST https://api.channel.io/open/v5/user-chats/{userChatId}/messages`
- 인증: 채널톡 Open API 문서의 "인증" 절 확인 후, Access Key/Secret을 헤더에 포함.

(정확한 파라미터명·요청 body 형식은 채널톡 최신 문서를 반드시 확인한다.)

---

## 6. 주의사항

- **비로그인 결제**: 결제 검증 API는 현재 로그인 필수이므로, 결제 완료 시점에는 항상 `userId`가 있다. 비로그인 결제를 도입할 경우에는 memberId를 넣을 수 없으므로 채널톡 알림은 건너뛰면 된다.
- **memberId와 userId 일치**: 부트 시 넣는 `memberId`와, 서버에서 알림 보낼 때 쓰는 `userId`가 동일한 값(우리 DB User.id)이어야 한다.
- **실패 시**: 채널톡 API 호출이 실패해도 결제 완료 응답(conversationId 반환)과 메시지창 리다이렉트는 그대로 유지한다.

이 순서대로 진행하면 "예약·결제 확정 후 메시지창으로 이동 + 채널톡 노티피케이션"이 구현된다.
