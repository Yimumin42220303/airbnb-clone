# 결제·취소·환불 운영 체크리스트

운영 배포 후 아래 항목을 순서대로 확인합니다.

## 1. 환경 변수

- `NEXT_PUBLIC_PORTONE_STORE_ID`가 `store-`로 시작하는지 확인
- `NEXT_PUBLIC_PORTONE_CHANNEL_KEY`가 현재 운영 채널 키인지 확인
- `PORTONE_API_SECRET`가 V2 Secret Key인지 확인
- `PORTONE_WEBHOOK_SECRET`가 설정되어 있는지 확인
- `CRON_SECRET`가 설정되어 있는지 확인
- `NEXT_PUBLIC_PORTONE_TEST_MODE`가 `true`가 아닌지 확인
- `ENABLE_MOCK_PAYMENT`, `NEXT_PUBLIC_ENABLE_MOCK_PAYMENT`가 운영에서 비활성인지 확인

## 2. 운영/테스트 모드

- 관리자 로그인 후 `GET /api/admin/portone-mode` 호출
- `summary`가 `실결제 모드 (실연동 채널 + 테스트플래그 없음)`인지 확인
- `channelKeyPrefix`가 현재 운영 채널과 일치하는지 확인

## 3. 웹훅

- PortOne 콘솔에 웹훅 URL이 `https://도메인/api/webhooks/portone`로 등록돼 있는지 확인
- 웹훅 시크릿이 콘솔 값과 서버 env 값이 같은지 확인
- 테스트 결제 1건 후 서버 로그에 `Invalid webhook signature`가 없는지 확인

## 4. Cron

- `CRON_SECRET`가 Production에 설정돼 있는지 확인
- Vercel Cron은 **GET**으로 호출함 → `/api/cron/*` route에 GET 핸들러 필요 (`export { POST as GET }`)
- 수동 테스트: `curl -H "Authorization: Bearer $CRON_SECRET" https://도메인/api/cron/cancel-unpaid` (GET 또는 POST)
- Production `CRON_SECRET`와 로컬 `.env` 값이 다르면 로컬 curl은 401 — Vercel Cron은 Production env 기준으로 동작
- `vercel.json` 기준 주요 스케줄 확인
- `cancel-unpaid`: `0 0 * * *` (Vercel Hobby 플랜 제한으로 일 1회)
- `charge-deferred`: `0 0 * * *`
- Vercel 배포 후 Cron 탭에서 최근 실행 이력이 생기는지 확인
- 미결제 자동 취소의 실시간성은 `cancelExpiredBookings()` 온디맨드 호출도 함께 담당하는지 확인
- 미결제 자동 취소 정책: `confirmedAt` 기준 **48시간(2일)** (즉시·승인제 공통)
- 결제 리마인더: 남은 결제 시간 **24시간 이내** 1회 (`paymentReminderSent`, cron 일 1회)
- 후불(`paymentMethod=deferred`) 예약은 자동 취소 대상에서 제외 (현재 UI 비활성)
- 온디맨드 취소 시에도 `notifyUnpaidAutoCancel`으로 이메일·인앱·시스템 메시지 발송되는지 확인

## 5. 즉시결제

- 예약 1건 생성 후 결제 페이지에서 실제 결제가 열리는지 확인
- 결제 완료 후 `booking.paymentStatus = paid`, `booking.status = confirmed`인지 확인
- `PaymentTransaction.amount`가 KRW 기준으로 저장되는지 확인
- 결제 완료 후 메시지방/이메일/Beds24 반영이 정상인지 확인

## 6. 취소 / 환불

- 결제 완료 예약 취소 시 정책별 환불 금액이 기대값과 맞는지 확인
- 환불 후 `booking.status = cancelled`, `paymentStatus = refunded`인지 확인
- 환불 트랜잭션이 기존 결제 `paymentId`와 다른 고유 `paymentId`로 저장되는지 확인
- 0% 환불 취소는 `status = cancelled`, `paymentStatus = paid`로 남는 것이 정책 의도와 맞는지 확인

## 7. 후불 결제

- 빌링키 예약이 있다면 자동 결제 시 PortOne 요청 금액이 KRW 환산값인지 확인
- 후불 성공 트랜잭션 `amount`도 KRW로 저장되는지 확인
- 실패 시 `paymentStatus = failed`로 바뀌는지 확인

## 8. 로그에서 볼 것

- `Webhook: signature verification failed`
- `Portone payment lookup failed`
- `Portone billing key payment failed`
- `CRON_SECRET is not configured`
- `Amount mismatch`

위 로그가 나오면 환경 변수 또는 PortOne 콘솔 설정을 먼저 다시 확인합니다.
