# 예약자 정보와 결제 성공 여부의 상관관계

## 요약

- **예약자 정보**(성함, 이메일, 긴급연락용 전화번호)는 **결제 요청 전에** `Booking`에 저장됩니다.
- **결제 성공 여부**는 PG(포트원/이니시스) 응답과 `/api/payments/verify` 검증 후 `Booking.paymentStatus`로만 갱신됩니다.
- **직접적 인과 관계는 없습니다.**  
  즉, “예약자 정보를 어떻게 입력했는지”가 결제 성공/실패를 **직접** 결정하지는 않습니다.  
  다만 **전화번호가 없으면 이니시스 결제 요청 자체가 차단**되므로, “결제 시도 가능 여부”와는 상관이 있습니다.

---

## 1. 예약자 정보가 쓰이는 곳

### 1.1 입력 시점

- **예약 확인 페이지** (`/booking/confirm`)  
  - 예약자 성함 \*, 이메일 \*, 긴급연락용 전화번호 \*, 특별 요청사항(선택)
- 폼 제출 시 `POST /api/bookings` 로 전달:
  - `guestName`, `guestPhone` (이메일은 로그인 사용자 `User.email` 사용)

### 1.2 DB 저장

- **Prisma `Booking`**
  - `guestName` (String?): 예약 확인 페이지에서 입력한 성함
  - `guestPhone` (String?): 긴급연락용 전화번호
- `createBooking()` 내부에서 위 필드로 저장됨 (`lib/bookings.ts` → `api/bookings/route.ts`).

### 1.3 결제 창에 전달

- **결제 페이지** (`/booking/[id]/pay`) 의 `PayButton` 에서:
  - `userName` = `booking.guestName ?? me?.name`
  - `userPhoneNumber` = `booking.guestPhone ?? me?.phone`
- 포트원 `requestPayment` 호출 시:
  - `customer.fullName` = 위 `userName` (없으면 `"결제자"`)
  - `customer.phoneNumber` = 위 전화번호를 `normalizePhone()` 한 값
  - `customer.email` = 로그인 사용자 `me?.email` (예약자 정보 폼의 이메일과 동일 소스)

### 1.4 이니시스 결제 시 필수 조건

- `PayButton.tsx` 169–175행:
  - **휴대폰 번호가 없으면** 이니시스 결제 요청을 아예 하지 않고,  
    `"이니시스 결제를 위해 휴대폰 번호가 필요합니다. 마이페이지에서 휴대폰 번호를 등록해 주세요."` 로 **에러 처리**합니다.
- 따라서:
  - **예약 확인 단계에서 `guestPhone`을 넣지 않고**,  
    **마이페이지에 전화번호도 없으면** → 결제 버튼을 눌러도 **결제 창이 뜨기 전에 막힘** (결제 “실패”라기보다 “결제 시도 불가”).

## 2. 결제 성공이 기록되는 흐름

- 사용자가 결제 창에서 결제 완료
  - 포트원 SDK가 `paymentId` 등 반환
- 클라이언트가 `POST /api/payments/verify` 호출  
  - body: `{ paymentId, bookingId }`  
  - **예약자 성함/전화번호/이메일은 verify 요청에 포함되지 않음.**
- 서버(`api/payments/verify/route.ts`)에서:
  - `bookingId`로 `Booking` 조회
  - 포트원 서버에 `paymentId`로 결제 상태 조회
  - `status === "PAID"` 이고 금액 일치 시:
    - `Booking.paymentStatus = "paid"`, `status = "confirmed"` 등 갱신
    - `PaymentTransaction` 생성
    - `onPaymentVerified(bookingId)` 호출 (이메일/알림/메시지 등)
- **결제 성공 여부는 오직 “PG 응답 + 금액 검증”으로만 결정**되며,  
  예약자 정보 필드 값(성함/전화/이메일)은 이 검증 로직에 사용되지 않습니다.

---

## 3. 상관관계 정리

| 구분 | 내용 |
|------|------|
| **결제 성공/실패 결정** | PG 결제 결과 + `/api/payments/verify` 검증만 사용. **예약자 정보는 사용하지 않음.** |
| **결제 시도 가능 여부** | 이니시스 사용 시 **휴대폰 번호 필수**. `guestPhone` 또는 `User.phone`이 없으면 결제 요청 자체가 차단됨. |
| **데이터 상 연관** | 같은 `Booking` 레코드에 `guestName`/`guestPhone`과 `paymentStatus`가 함께 있으므로, **통계상** “전화번호 있는 예약 vs 없는 예약”의 결제 완료율을 비교하는 분석은 가능함. |
| **인과 관계** | “예약자 정보를 정확히 입력해서 결제 성공률이 올라간다”가 아니라, “전화번호가 없으면 이니시스 결제 시도가 막혀서 결제 완료로 이어질 수 없다”에 가깝습니다. |
