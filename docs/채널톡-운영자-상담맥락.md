# 채널톡 운영자 — 상담 맥락 필드 안내

게스트 UX는 변경하지 않고, **채널톡 데스크**에서 상담원이 조건·숙소 맥락을 바로 볼 수 있도록 `tokyominbak*` 프로필 필드를 전송합니다.

관련 구현: `src/lib/channel-context-summary.ts`, `recommend-channel-talk.ts`, `ListingChannelInquiryButton.tsx`

연동 전체: [채널톡-서비스-연동.md](./채널톡-서비스-연동.md)

---

## 1. 데스크에서 먼저 할 설정 (필수)

코드에서 필드를내도 **채널톡 데스크에 커스텀 프로필 필드를 등록·표시하지 않으면** 상담창에 안 보일 수 있습니다.

1. 채널톡 데스크 → **설정** → **고객 정보** / **사용자 프로필** (메뉴명은 채널 버전에 따라 다름)
2. 아래 필드를 **사용자 프로필**에 추가 (필드 키는 코드와 동일하게)
3. 상담 화면 **오른쪽 고객정보 패널 상단**에 다음을 우선 노출 권장:
   - `tokyominbakContextSummary` (한 줄 요약)
   - `tokyominbakSearchCondition`
   - `tokyominbakLeadCode` (추천 상담 시)
4. 상세는 `tokyominbakContextDetail` 또는 펼침 영역에 배치

| 필드 키 | 설명 |
|---------|------|
| `tokyominbakContextType` | `recommendation` / `listing_inquiry` / `general` |
| `tokyominbakContextSummary` | **가장 먼저 볼 한 줄** (220자 이내) |
| `tokyominbakContextDetail` | 조건·숙소 상세 (800자 이내) |
| `tokyominbakContextUrl` | 상담 발생 페이지 URL |
| `tokyominbakLeadCode` | 추천 리드 번호 (추천 상담만) |
| `tokyominbakListingSummary` | 숙소명 요약 |
| `tokyominbakListingIds` | 숙소 ID (쉼표 구분) |
| `tokyominbakSearchCondition` | 일정·인원·지역 등 한 줄 |
| `tokyominbakContextUpdatedAt` | 맥락 갱신 시각 (ISO) |

## 2. 추천 상담 (`/recommend` → 상담 시작하기)

### 게스트 동작 (변경 없음)

조건 입력 → 추천 결과 → **상담 시작하기** → 리드 저장 → 채널톡 메신저 오픈

### 데스크에서 보이는 맥락

| 구분 | 내용 |
|------|------|
| 타입 | `tokyominbakContextType` = `recommendation` |
| 한 줄 예시 | `[추천상담] 2026.07.12~07.15 · 3명 · 신주쿠/시부야 · 가격우선 · 예산 20~25만/박 · 후보 3개` |
| 리드 | `tokyominbakLeadCode`, 기존 `recommendLeadCode` 동일 값 |
| 기존 필드 유지 | `recommendCheckIn`, `recommendGuestCount`, `recommendPreferredArea` 등 |

### 개인정보

이름·이메일·freeText는 **추천 상담 profile에 넣지 않음** (기존 정책). 로그인 게스트는 전역 위젯이 name/email을 넘길 수 있음.

## 3. 숙소 상세 문의 (`/listing/[id]` → 숙소 문의)

### 게스트 동작 (변경 없음)

숙소 문의 버튼 클릭 → 채널톡 메신저 오픈 (추가 입력·모달 없음)

### 일정·인원

URL query (`checkIn`, `checkOut`, `adults`, `children`, `guests` 등)에 값이 있을 때만 summary/detail에 반영. 없으면 **「일정/인원 미입력」**.

### 데스크에서 보이는 맥락

| 구분 | 내용 |
|------|------|
| 타입 | `tokyominbakContextType` = `listing_inquiry` |
| 한 줄 예시 (조건 없음) | `[숙소문의] 신주쿠역 2분 숙소 · 일정/인원 미입력 · 상세페이지에서 문의` |
| 한 줄 예시 (URL에 일정·인원) | `[숙소문의] 신주쿠역 2분 숙소 · 2026.07.12~07.15 · 3명 · 상세페이지에서 문의` |
| 기존 필드 유지 | `inquiryListingId`, `listing_inquiry` 태그 등 |

## 4. 수동 테스트 방법

### 추천 상담

1. `/recommend`에서 조건 입력 후 추천 → **상담 시작하기**
2. 브라우저 개발자 도구 → Network 또는 ChannelIO 호출 전 `updateUser` payload 확인
3. `tokyominbakContextSummary`, `tokyominbakLeadCode`, `recommendLeadCode` 존재 확인
4. 채널톡 데스크에서 해당 사용자 상담 열기 → 프로필 패널에 summary 표시 확인

### 숙소 문의

1. `/listing/{id}?checkIn=2026-07-12&checkOut=2026-07-15&adults=2` 접속 후 **숙소 문의**
2. summary에 일정·인원 반영 확인
3. query 없이 접속 후 문의 → 「일정/인원 미입력」 확인

### 회귀

- 전역 런처·카카오 폴백·리드 API·결제/예약 플로우 영향 없음

### Stale context (맥락 잔류) QA

| 시나리오 | 기대 동작 |
|----------|-----------|
| A. 추천 상담 → 다른 숙소 **숙소 문의** | `tokyominbakContextType`=listing_inquiry, Summary=[숙소문의], `recommend*`·`tokyominbakLeadCode`는 **null로 초기화** 후 갱신 |
| B. URL 없이 숙소 문의 | Summary에 **일정/인원 미입력** (이전 추천 일정이 summary에 섞이지 않음) |
| C. `?checkIn&checkOut&adults` 후 숙소 문의 | Summary에 해당 일정·인원 반영 |
| D. **일반 런처**만 클릭 | 마지막 맥락이 user profile에 남을 수 있음 → **`tokyominbakContextUpdatedAt`으로 최신 여부 확인** |

코드: 숙소 문의 시 `RECOMMEND_CHANNEL_PROFILE_CLEAR`, 추천 상담 시 `LISTING_INQUIRY_CHANNEL_PROFILE_CLEAR` (`channel-context-summary.ts`).

## 5. 필드가 안 보일 때

| 원인 | 조치 |
|------|------|
| 데스크 프로필 필드 미등록 | §1 설정 |
| 게스트가 채널톡 SDK 로드 전 이탈 | 재시도·카카오 폴백 (추천) |
| Open API 알림과 무관 | 이번 필드는 **Web SDK profile** 전용 |

---

## 6. 배포 전 주의

- **DB·환경 변수 변경 없음** — 코드 배포만으로 동작
- 데스크 프로필 필드 설정은 **운영자가 프로덕션 채널에도 동일하게** 적용해야 함
- 필드 키 이름 변경 시 코드·데스크 설정을 함께 수정
