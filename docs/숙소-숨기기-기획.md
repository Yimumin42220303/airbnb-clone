# 호스트 숙소 'OTA 숨기기' 기능 기획

## 1. 목적

- 각 호스트가 **자기가 등록한 숙소**를 OTA(도쿄민박) 상에서 **일시적으로 비공개**로 전환할 수 있게 한다.
- 숨긴 숙소는 **검색·홈·상세 노출에서 제외**되며, **기존 예약·캘린더·정산·Beds24 연동**은 그대로 유지한다.

---

## 2. 정책 정의

| 구분 | 숨김(OFF) | 숨김(ON) |
|------|-----------|----------|
| **의미** | OTA에 정상 노출 | OTA에서 발견 불가 |
| **검색/홈** | 노출됨 | 제외 |
| **상세 페이지** (`/listing/[id]`) | 접근 가능 | 비공개 안내 또는 404 |
| **새 예약** | 가능 | 불가(상세 진입 불가) |
| **기존 예약** | — | 그대로 유지 (게스트·호스트 모두 조회/메시지 가능) |
| **호스트 대시보드** | 목록에 표시 | 목록에 표시 + "숨김" 표시 |
| **캘린더/가격 동기화** | — | Beds24·iCal 등 연동 유지 (선택) |
| **sitemap** | 포함 | 제외 |
| **위시리스트** | — | 숨긴 숙소는 목록에서 제외하거나 "비공개" 표시 (정책 선택) |

- **어드민 승인(`status`)** 과 독립: `approved` 여부와 관계없이, 호스트가 숨기면 OTA에서는 비공개로 간주한다.
- 숨기기 **ON/OFF는 호스트만** 변경 가능 (본인 숙소만).

---

## 3. 데이터 모델

### 3.1 스키마 (Prisma)

`Listing` 모델에 필드 1개 추가:

```prisma
/// OTA 노출 숨김: true면 검색·상세·홈 등에 노출하지 않음 (호스트는 목록에서 조회·토글 가능)
hidden  Boolean  @default(false)
```

- 기본값 `false`: 기존 숙소는 모두 “노출” 상태로 동작.
- 마이그레이션: `ALTER TABLE "Listing" ADD COLUMN "hidden" BOOLEAN NOT NULL DEFAULT false;`

### 3.2 기존 필드와의 관계

- `status` (pending / approved / rejected): **어드민 게재 승인**.
- `hidden`: **호스트 노출 on/off**.
- **공개 노출 조건**: `status === "approved" && hidden === false`.

## 4. 영향 범위 및 수정 포인트

### 4.1 공개 노출 제어 (숨긴 숙소 제외)

| 위치 | 파일 | 변경 내용 |
|------|------|-----------|
| 목록/검색/홈 | `src/lib/listings.ts` | `getListings()`의 `where`에 `hidden: false` 추가 |
| 상세 조회 | `src/lib/listings.ts` | `getListingById()`의 `where`에 `hidden: false` 추가 |
| sitemap | `src/app/sitemap.ts` | `status: "approved", hidden: false` 조건으로 목록 조회 |
| API 목록 | `GET /api/listings` | `getListings()` 사용 시 자동 반영 (추가 수정 없음) |

### 4.2 상세 페이지 접근 시 (숨긴 숙소)

- **권장**: `getListingById()`가 이미 `hidden: false`를 넣으므로, 숨긴 숙소는 `null` → **404**.
- **대안**: “이 숙소는 현재 비공개입니다” 전용 페이지를 두고, `getListingById(id, { allowHidden: false })` 등으로 분기해 리다이렉트. (우선 404로 단순화 가능.)

### 4.3 호스트 측

| 위치 | 파일 | 변경 내용 |
|------|------|-----------|
| 호스트 숙소 목록 API | `src/app/api/host/listings/route.ts` | `select`에 `hidden` 추가 (호스트는 모든 본인 숙소 조회) |
| 호스트 숙소 목록 페이지 | `src/app/host/listings/page.tsx` | 서버에서 가져온 목록에 `hidden` 포함해 전달 |
| 호스트 목록 UI | `src/components/host/HostListingsContent.tsx` | 카드에 “OTA 숨김” 배지 표시, (선택) 빠른 토글 |
| 숙소 수정 폼 | `EditListingForm.tsx` | “OTA에서 숨기기” 토글 추가, submit 시 `hidden` 전송 |
| 숙소 등록 폼 | `NewListingForm.tsx` | (선택) 신규 등록 시 기본값 `hidden: false`만 명시 |
| 수정 API | `PATCH /api/listings/[id]` | body에서 `hidden` 받아 `updateListing()`에 전달 |
| 등록 API | `POST /api/listings` | (선택) `hidden` 기본값 처리 |

### 4.4 그 외

| 위치 | 파일 | 변경 내용 |
|------|------|-----------|
| 위시리스트 | `src/app/wishlist/page.tsx` | 숨긴 숙소 제외: `listing.status === "approved" && listing.hidden === false` 등으로 필터. 또는 노출하되 “비공개” 문구 표시 (정책에 따라 선택) |
| 추천/메인 노출 | `src/app/api/recommend/*`, `src/app/page.tsx` | 이미 `getListings()` 또는 approved 목록 사용 시, `getListings()`에 `hidden: false`만 넣으면 자동 반영 |
| Mock 페이지 | `src/app/mock/page.tsx` | (선택) 테스트용 목록 조회 시 `hidden: false` 포함 |
| 어드민 목록 | `src/app/admin/listings/page.tsx` | 어드민은 전체 조회 유지, 컬럼에 “숨김” 표시만 추가하면 됨 |

### 4.5 변경하지 않는 부분

- **예약·결제·환불·정산**: booking은 `listingId` 기준이므로, 숙소를 숨겨도 기존 예약/메시지/정산 로직 변경 불필요.
- **캘린더·가격 동기화**: Beds24 / iCal 등은 `listingId` 기준이므로 그대로 두어도 됨. (숨겨도 연동 유지 가능.)
- **리뷰·블록 일정**: 숙소 단위 API는 모두 listing 존재 여부만 확인하므로, 숨김 여부와 무관하게 동작하게 둘 수 있음.

## 5. UI/UX 요구사항

### 5.1 호스트: 숙소 목록

- 각 숙소 카드에 **상태 배지** 하나 추가:
  - `approved` + `!hidden` → “게재 중” (기존과 동일)
  - `approved` + `hidden` → “OTA 숨김” (회색 또는 보조 색)
  - `pending` / `rejected` → 기존처럼 “승인 대기” / “거절”
- (선택) 카드 또는 목록에서 **즉시 토글**로 숨기기/해제 가능하게 할 수 있음.

### 5.2 호스트: 숙소 수정 폼

- **“OTA 노출” 섹션** 추가 (예: 취소 정책 위나 아래).
  - 라벨: “OTA에서 숨기기” / “검색·상세에 숨기기” 등.
  - 설명: “켜면 게스트 검색과 숙소 상세에 노출되지 않습니다. 기존 예약에는 영향 없습니다.”
  - **토글** 또는 라디오: “노출함” / “숨김”.
- 저장 시 `hidden` 값을 API로 전달.

### 5.3 다국어 (호스트)

- `src/lib/host-i18n/translations.ts`에 예:
  - `listings.hiddenBadge`: "OTA 숨김" / "非表示"
  - `edit.hideOnOta`: "OTA에서 숨기기" / "OTAで非表示にする"
  - `edit.hideOnOtaDescription`: "켜면 검색·상세에 노출되지 않습니다. 기존 예약에는 영향 없습니다." / 日文

## 6. API 스펙 요약

### 6.1 PATCH `/api/listings/[id]`

- **Body** (기존 + 추가): `{ ..., "hidden": boolean }`
- 본인 숙소만 수정 가능 (기존 권한 유지).
- 응답에 수정된 `listing` 포함 시 `hidden` 포함.

### 6.2 GET `/api/host/listings`

- 응답 각 항목에 `hidden: boolean` 추가.
- 호스트는 자신의 모든 숙소를 보므로, `where: { userId }`만 유지하고 select에 `hidden`만 추가.

---

## 7. 구현 순서 제안

1. **DB**: `Listing`에 `hidden` 컬럼 추가, 마이그레이션 적용.
2. **공개 쿼리**: `getListings()`, `getListingById()`에 `hidden: false` 반영.
3. **sitemap**: approved + not hidden 만 포함.
4. **호스트 API**: `GET /api/host/listings`에 `hidden` 포함, `PATCH /api/listings/[id]`에서 `hidden` 수정 가능하게.
5. **listings 라이브러리**: `createListing` / `updateListing` 타입·함수에 `hidden` 추가.
6. **호스트 UI**: 목록 배지, 수정 폼 토글, 번역 추가.
7. **위시리스트**: 숨긴 숙소 제외 또는 “비공개” 표시 (정책 확정 후).
8. **(선택)** 상세 페이지에서 숨긴 숙소 접근 시 전용 “비공개” 페이지로 리다이렉트.

## 8. 테스트 체크리스트

- [ ] 숨기기 OFF → 검색/홈/상세 노출, sitemap 포함.
- [ ] 숨기기 ON → 검색/홈에서 제외, 상세 404, sitemap 제외.
- [ ] 호스트 목록에서 숨긴 숙소 보이고 “OTA 숨김” 표시.
- [ ] 수정 폼에서 토글 변경 후 저장 시 API로 반영.
- [ ] 숨긴 숙소에 대한 기존 예약: 게스트/호스트 예약 목록·메시지 정상.
- [ ] 숨긴 숙소로의 새 예약 불가 (상세 404이므로 예약 플로우 진입 불가).
- [ ] 위시리스트: 숨긴 숙소 제외 또는 표시 방식 확인.

## 9. 요약

- **한 줄**: 호스트가 “OTA에서 숨기기”를 켜면, 해당 숙소는 `hidden: true`로 저장되고, 공개용 모든 노출(검색·홈·상세·sitemap)에서 제외된다. 호스트는 자신의 목록에서 계속 보고 토글할 수 있으며, 기존 예약·연동은 유지된다.
- **범위**: 스키마 1필드, 공개 조회 2곳, sitemap 1곳, 호스트 API 2곳, 호스트 UI(목록+수정폼), 위시리스트 정책 1곳.
