## 2. 글 작성 시 제출해야 할 필드

아래 6개 필드를 **JSON 형식**으로 출력해 줘.

```json
{
  "title": "글 제목",
  "slug": "url-용-슬러그",
  "excerpt": "1~2문장 요약 (메타 디스크립션용, 최대 160자)",
  "coverImage": "(선택) 대표 이미지 URL 또는 이미지 제안 설명",
  "body": "본문 전체 텍스트",
  "published": true
}
```

### 각 필드 규칙

| 필드 | 규칙 |
|------|------|
| **title** | 핵심 키워드를 앞쪽에 배치. 30~50자 내외. "도쿄", "숙소", "민박" 등 주요 키워드 1~2개 포함 |
| **slug** | 한글 가능. 띄어쓰기 대신 `-` 사용. 핵심 키워드 포함. 예: `도쿄-1인-숙소-추천-2026` |
| **excerpt** | 검색 결과에 노출될 메타 디스크립션. 1~2문장, 120~160자. 글의 핵심 가치를 명확히 전달 |
| **coverImage** | 직접 URL이 없으면 `"(제안) 신주쿠 거리 야경 사진"` 처럼 이미지 설명을 적어줘. 운영자가 별도로 업로드함 |
| **body** | 아래 **본문 작성 규칙** 참고 |
| **published** | 항상 `true` |

---

## 3. 본문(body) 작성 규칙

### 3-1. 포맷

- **HTML이 아닌 순수 텍스트**로 작성
- 줄바꿈은 `\n` (실제 개행문자)으로 처리 → 화면에서 `<br />`로 변환됨
- 단락 구분은 **빈 줄 하나** (`\n\n`)
- 마크다운 문법(##, **, - 등)은 **사용하지 않음** (렌더링되지 않음)
- 이모지 사용 가능하나 과도하게 쓰지 않기

### 3-2. 이미지 삽입

본문 중간에 이미지를 넣고 싶은 위치에 아래 형식 사용:

```
[IMG:https://example.com/photo.jpg]
```

- URL은 반드시 `https://`, `http://`, `/`로 시작해야 함
- 직접 URL이 없으면 `[IMG:(제안) 아사쿠사 센소지 사진]`처럼 플레이스홀더 작성
- 본문 시작 직후, 주제 전환 지점, 글 마무리 전 등 **3~5곳**에 이미지 위치 표시 권장

### 3-3. 본문 구조 (권장 템플릿)

```
[도입부 - 2~3줄]
독자의 고민/상황에 공감하며 시작. "도쿄 여행 숙소, 어디서 잡아야 할지 고민되시죠?"

[IMG:(제안) 도쿄 시부야 스크램블 교차로]

[핵심 내용 1 - 소제목 느낌의 한 줄 + 설명 3~5줄]
소제목을 굵게 쓸 수 없으므로, 한 줄로 "◆ 신주쿠 – 교통의 중심" 같이 기호를 활용

[핵심 내용 2]
...

[IMG:(제안) 관련 사진]

[핵심 내용 3]
...

[정리/비교 - 간단한 텍스트 표 또는 요약]

[IMG:(제안) 관련 사진]

[마무리 - CTA 포함]
"도쿄민박에서 직접 검증한 숙소를 확인해 보세요 → tokyominbak.net"
```

### 3-4. 소제목·강조 표현

마크다운/HTML을 쓸 수 없으므로 아래 방식으로 구조감 부여:

| 용도 | 표현 방법 | 예시 |
|------|-----------|------|
| 소제목 | 기호 + 텍스트 | `◆ 신주쿠 – 쇼핑과 유흥의 중심` |
| 번호 목록 | 숫자 + 마침표 | `1. 위치가 좋은 숙소` |
| 불릿 목록 | 기호 | `• 체크인 15:00 / 체크아웃 10:00` |
| 강조 | 【】 또는 「」 | `【주의】 골든위크 기간은 가격이 2배 이상` |
| 구분선 | 빈 줄 + 기호 | `──────────` |

## 4. SEO 최적화 규칙

### 4-1. 키워드 전략

- **주요 타깃 키워드**를 title, slug, excerpt, 본문 첫 100자 안에 자연스럽게 포함
- 키워드 밀도: 본문 전체에서 주요 키워드가 **3~5회** 등장 (억지 반복 금지)
- LSI(관련) 키워드를 자연스럽게 섞기
  - 예: "도쿄 숙소" → "도쿄 민박", "도쿄 호텔", "도쿄 게스트하우스", "에어비앤비 도쿄"

### 4-2. 검색 의도(Search Intent) 매칭

| 의도 | 글 유형 | 예시 |
|------|---------|------|
| 정보형 | 가이드, 비교, 팁 | "도쿄 1인 여행 숙소 고르는 법" |
| 거래형 | 추천, 리스트 | "2026년 도쿄 가성비 숙소 BEST 5" |
| 탐색형 | 지역 소개, 후기 | "시부야 vs 신주쿠, 어디서 묵을까?" |

### 4-3. 콘텐츠 길이

- **최소 1,500자 ~ 권장 2,500~3,500자** (한글 기준)
- 너무 짧으면 SEO 효과 약하고, 너무 길면 이탈률 증가

## 5. AEO(AI Engine Optimization) 최적화 규칙

AI 검색엔진(ChatGPT, Perplexity, Google SGE)이 답변 소스로 인용하기 좋게 작성.

### 5-1. 핵심 원칙

- **질문-답변 구조**: 독자가 검색할 법한 질문을 본문에 포함하고 바로 답변
- **Answer-First**: 결론/답변을 먼저 쓰고, 그 뒤에 상세 설명
- **사실 기반**: 가격, 소요 시간, 거리 등 구체적 수치 포함
- **최신 정보**: 연도(2026년)를 명시하여 정보의 시의성 확보

### 5-2. FAQ 삽입

본문 후반부에 **자주 묻는 질문 2~4개**를 Q&A 형식으로 포함:

```
◆ 자주 묻는 질문

Q. 도쿄 민박은 에어비앤비보다 저렴한가요?
A. 네, 도쿄민박에 등록된 숙소는 플랫폼 수수료가 낮아 동일 숙소 기준 평균 10~20% 저렴합니다. 또한 한국어 고객지원이 포함되어 있어 추가 비용 없이 편리하게 이용 가능합니다.

Q. 체크인·체크아웃 시간은 어떻게 되나요?
A. 숙소마다 다르지만, 일반적으로 체크인 15:00 이후, 체크아웃 10:00~11:00입니다. 정확한 시간은 각 숙소 상세 페이지에서 확인하세요.
```

### 5-3. 인용 가능한 문장

AI가 추출하기 좋도록, 핵심 정보를 **한 문장으로 완결**되게 작성:

- 좋은 예: "신주쿠역에서 도보 5분 거리의 도쿄 민박은 1박 평균 8만~12만 원으로 이용할 수 있습니다."
- 나쁜 예: "가격은 저렴한 편이고 위치도 괜찮습니다."

## 11. ChatGPT로 작성·업로드 자동화 (Custom GPT + API)

ChatGPT가 **아티클 작성 + tokyominbak.net에 바로 등록**까지 하게 하려면 **Custom GPT**에 **Action**을 연결하면 됩니다.

### 11-1. 흐름

1. 사용자가 ChatGPT에게 "오늘 블로그 글 써줘, 주제: 시부야 숙소 추천" 요청
2. ChatGPT가 가이드라인에 따라 글 작성 후 JSON 생성
3. ChatGPT가 **Action**으로 우리 서버 `POST /api/admin/blog/from-api` 호출
4. 서버가 API 키를 검증한 뒤 DB에 글 저장 → 블로그에 즉시 반영

### 11-2. 서버 설정 (운영자)

1. **API 키 생성**  
   터미널에서 `openssl rand -hex 24` 실행 후 나온 48자 문자열을 복사합니다.

2. **환경 변수 설정**  
   로컬 `.env` 및 Vercel 프로젝트 Environment Variables에 추가:
   - `BLOG_AUTO_PUBLISH_API_KEY` = 위에서 복사한 48자 문자열
   - `BLOG_AUTHOR_USER_ID` = (선택) 글 작성자로 쓸 관리자 User ID(cuid). 비우면 DB에서 첫 번째 admin 계정 사용

3. **엔드포인트**
   - URL: `https://tokyominbak.net/api/admin/blog/from-api` (또는 배포된 사이트 기준 URL)
   - 메서드: `POST`
   - 인증: 요청 헤더에 `x-api-key: {BLOG_AUTO_PUBLISH_API_KEY}` 또는 `Authorization: Bearer {BLOG_AUTO_PUBLISH_API_KEY}`

4. **요청 본문 (JSON)**  
   가이드라인 2절의 6개 필드 그대로 전달:
   - `title` (필수), `slug`, `excerpt`, `coverImage`, `body` (필수), `published`

5. **응답 예시**
   - 성공 200: `{ "ok": true, "id": "...", "slug": "...", "url": "https://tokyominbak.net/blog/...", "published": true }`
   - 실패 400/401/500: `{ "error": "메시지" }`

### 11-3. Custom GPT 설정 (ChatGPT Plus 사용자)

> **더 구체적인 설정 방법**(화면별 단계, 복사용 문구, 인증 설정)은 **`docs/Custom-GPT-블로그-설정-가이드.md`** 를 참고하세요.

1. ChatGPT에서 **Explore GPTs** → **Create** → Custom GPT 생성
2. **Instructions**에 이 가이드라인 문서 전체(또는 1~10절 요약)를 붙여넣고, 마지막에 다음을 추가:

   ```
   글 작성이 완료되면 반드시 create_blog_post 액션을 호출하여 tokyominbak.net에 등록해 줘.
   사용자가 "업로드하지 마"라고 하지 않는 한, JSON 출력 후 곧바로 API를 호출해 줘.
   ```

3. **Actions** 탭에서 **Create new action** 선택
4. **Schema**에 아래 OpenAPI 스키마를 붙여넣고, `SERVER_URL`을 실제 배포 URL로 바꿈:

```yaml
openapi: 3.0.0
info:
  title: 도쿄민박 블로그 등록 API
  version: 1.0.0
servers:
  - url: https://tokyominbak.net
paths:
  /api/admin/blog/from-api:
    post:
      summary: 블로그 글을 도쿄민박 사이트에 등록
      operationId: create_blog_post
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [title, body]
              properties:
                title: { type: string, description: "글 제목" }
                slug: { type: string, description: "URL용 슬러그 (한글 가능, - 구분)" }
                excerpt: { type: string, description: "메타 설명 120~160자" }
                coverImage: { type: string, description: "대표 이미지 URL 또는 (제안) 설명" }
                body: { type: string, description: "본문 전체. 줄바꿈 \\n, 이미지 [IMG:url]" }
                published: { type: boolean, description: "true=즉시 공개, false=초안" }
      responses:
        "200":
          description: 등록 성공
        "400":
          description: 필수 필드 누락 등
        "401":
          description: API 키 오류
```

5. **Authentication**에서 **API Key** 선택
   - Type: **Bearer** (또는 Custom: `x-api-key` 헤더에 동일 키 입력)
   - Key: `BLOG_AUTO_PUBLISH_API_KEY` 값 입력

6. GPT 저장 후, 대화에서 "오늘 블로그 글 써줘. 주제: 신주쿠 1인 숙소 추천"처럼 요청하면 ChatGPT가 글을 작성하고 같은 대화 안에서 API를 호출해 글이 사이트에 올라갑니다.

### 11-4. 주의사항

- **coverImage**가 `(제안) ...` 형태면 서버에서 URL이 아니므로 저장하지 않고, 나중에 관리자 페이지에서 이미지를 업로드해 넣을 수 있습니다.
- API 키는 **절대** 공개 저장소나 클라이언트 코드에 넣지 말고, 서버 환경 변수와 Custom GPT 설정에만 둡니다.
- 초안으로 올리려면 사용자가 "published: false로 올려줘"라고 하면 됩니다.

## 12. 하루에 하나씩 자동 작성·업로드 (Vercel Cron)

**사람이 매일 ChatGPT를 열지 않아도**, 서버가 매일 정해진 시각에 글을 생성해 올리게 할 수 있습니다.

### 12-1. 동작 방식

1. **Vercel Cron**이 매일 **01:00 UTC(한국 10:00)** 에 `POST /api/cron/blog-daily` 호출
2. 서버가 **오늘 날짜**에 해당하는 **주제**를 `src/lib/blog-daily-topics.ts` 목록에서 선택 (날짜별 순환)
3. **OpenAI API**(gpt-4o-mini)로 해당 주제의 블로그 글 생성 요청
4. 응답 JSON을 파싱한 뒤 **같은 서버**의 `POST /api/admin/blog/from-api` 로 전달 → DB 저장 → 블로그에 공개

### 12-2. 필요한 환경 변수

| 변수 | 설명 |
|------|------|
| `CRON_SECRET` | Vercel Cron 인증용 (기존 크론과 동일) |
| `OPENAI_API_KEY` | 블로그 글 생성용 (기존 AI 추천과 동일 키 사용 가능) |
| `BLOG_AUTO_PUBLISH_API_KEY` | from-api 호출 시 인증용 (11절과 동일) |
| `BLOG_AUTHOR_USER_ID` | (선택) 글 작성자. 없으면 첫 번째 admin 사용 |

Vercel 대시보드 → 프로젝트 → Settings → Environment Variables 에서 **Production**에 설정합니다.

### 12-3. 실행 시각 변경

`vercel.json` 의 `crons` 배열에서 `blog-daily` 의 `schedule` 을 수정합니다.

- `"0 1 * * *"` = 매일 01:00 UTC (한국 10:00)
- `"0 0 * * *"` = 매일 00:00 UTC (한국 09:00)
- [cron 표현식](https://crontab.guru/) 으로 요일·시간 조정 가능

### 12-4. 주제 목록 수정

`src/lib/blog-daily-topics.ts` 의 `BLOG_DAILY_TOPICS` 배열을 수정하면 됩니다. 주제 개수만큼 순환하므로, 60개면 약 2달마다 같은 주제가 다시 나옵니다. SEO 전략에 맞게 주제를 추가·삭제·순서 변경하세요.

### 12-5. 수동 실행 (테스트)

배포된 사이트에서 Cron을 기다리지 않고 바로 한 번 돌려보려면:

```bash
curl -X POST "https://tokyominbak.net/api/cron/blog-daily" \
  -H "Authorization: Bearer YOUR_CRON_SECRET"
```

성공 시 응답 예: `{"ok":true,"topic":"...","date":"2026-03-03","post":{"id":"...","slug":"...","url":"..."}}`

### 12-6. 실패 시

- **401**: `CRON_SECRET` 이 없거나 Authorization 헤더가 틀림
- **500 OPENAI_API_KEY**: OpenAI 키 미설정
- **500 BLOG_AUTO_PUBLISH_API_KEY**: 블로그 API 키 미설정
- **500 AI 응답/JSON 파싱**: 모델이 JSON이 아닌 텍스트를 반환한 경우. 재실행하거나 `src/lib/blog-daily-prompt.ts` 로 프롬프트 조정

Vercel 대시보드 → Deployments → 해당 배포 → Logs 에서 크론 실행 로그를 확인할 수 있습니다.

## 참고: 기술적 제약 사항

- 본문에 **HTML 태그, 마크다운 문법은 렌더링되지 않음** (순수 텍스트 + `[IMG:url]`만 지원)
- `\n`이 `<br />`로 변환되므로 줄바꿈으로 단락·구조를 표현
- category, tags 필드는 현재 시스템에 없음 (향후 추가 가능)
- slug는 한글 사용 가능하며, 브라우저에서 자동 인코딩 처리됨
- 대표 이미지(coverImage)는 운영자가 별도 업로드 후 URL을 입력하는 방식
