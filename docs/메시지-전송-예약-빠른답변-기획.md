# 메시지 '예약 메시지(Scheduled Messages)' 기능 기획

> Airbnb의 "전송 예약된 빠른 답변(Scheduled Quick Replies)" 기능을 분석하고,
> 도쿄민박 OTA에 **한 번에** 구현할 수 있도록 설계한 통합 기획서.

---

## 1. Airbnb 기능 분석 요약

### 1.1 개요
- 호스트가 **메시지 템플릿을 만들고**, 예약 이벤트(예약 확정·체크인·체크아웃 등)에 맞춰 **자동 전송 스케줄**을 설정.
- 예약이 발생하면 해당 숙소에 연결된 템플릿들이 **자동으로 각 대화에 스케줄 인스턴스**로 생성됨.
- 호스트는 각 대화에서 **타임라인** 형태로 완료/대기 상태를 보고, 대기 건에 대해 **지금 보내기 / 건너뛰기** 가능.

### 1.2 트리거 이벤트 (Airbnb 기준)
| 트리거 | 설명 | 권장 시점 |
|--------|------|-----------|
| 예약 확정 시 | 예약이 확정(결제 완료)되면 즉시 또는 N시간/일 후 | 즉시~1시간 후 |
| 체크인 전 | 체크인 N일 전 (최대 14일 전까지) | 1~2일 전 |
| 체크인 당일 | 체크인 당일 특정 시각 | 오전 10시 등 |
| 체크인 후 (첫날) | 체크인 다음 날 | 체크인+1일 오전 |
| 체크아웃 전 | 체크아웃 전날 저녁 | 체크아웃-1일 오후 8시 등 |
| 체크아웃 후 | 체크아웃 다음 날 | 체크아웃+1일 오전 |

### 1.3 템플릿 구조
- **제목**: 호스트가 관리용으로 식별 (예: "(Shibuya) When reserved", "(All)Check in Guide")
- **본문**: 게스트에게 보내질 실제 메시지. **단축 코드(변수)**를 포함할 수 있음.
- **적용 범위**: 전체 숙소 또는 특정 숙소만.
- **트리거 + 타이밍**: 이벤트 종류 + 오프셋(N일 전/후) + 시각(그 숙소의 타임존 기준).

### 1.4 사용 가능한 단축 코드 (Airbnb 50+개 중 주요)
| 카테고리 | 코드 | 설명 |
|----------|------|------|
| 게스트 | `{guest_name}` | 게스트 이름 |
| 예약 | `{checkin_date}` | 체크인 날짜 |
| 예약 | `{checkout_date}` | 체크아웃 날짜 |
| 예약 | `{checkin_time}` | 체크인 시각 |
| 예약 | `{checkout_time}` | 체크아웃 시각 |
| 예약 | `{guests_count}` | 인원 수 |
| 예약 | `{nights}` | 박수 |
| 예약 | `{total_price}` | 총 금액 |
| 예약 | `{confirmation_code}` | 예약 확인 코드 |
| 숙소 | `{listing_name}` | 숙소 이름 |
| 숙소 | `{listing_address}` | 숙소 주소 |
| 숙소 | `{house_rules}` | 주의사항 |
| 호스트 | `{host_name}` | 호스트 이름 |

### 1.5 대화 내 UI
- 메시지 입력란 옆 **+ 버튼** → "전송 예약된 빠른 답변 보기"
- 모달/패널에서 **타임라인**: 완료(sent) / 대기(pending) / 건너뜀(skipped)
- 대기 건: [건너뛰기] [지금 보내기] 버튼
- 완료 건: "전송 완료: O월 O일 오후 O:OO" 또는 "수동 전송됨"

## 2. 도쿄민박 적용 설계

### 2.1 전체 흐름

```
[호스트] 템플릿 생성 (제목·본문·트리거·타이밍·적용 숙소)
                       ↓
[시스템] 예약 확정(결제 완료) 시 → 해당 숙소에 매칭되는 템플릿들로
         ScheduledMessage 인스턴스 자동 생성 (각각 전송 시각 계산)
                       ↓
[Cron] 매 10분 실행 → scheduledAt <= now && status=pending 인 건을
       Message로 전송 후 status=sent 갱신
                       ↓
[호스트] 대화창에서 타임라인 확인 → 대기 건 "지금 보내기" / "건너뛰기"
```

### 2.2 기능 범위 (한 번에 구현)

| 기능 | 설명 |
|------|------|
| **템플릿 CRUD** | 호스트가 직접 템플릿 생성·수정·삭제. 적용 숙소 지정(전체 or 특정) |
| **단축 코드** | 본문에 `{guest_name}`, `{checkin_date}` 등 삽입 → 전송 시 실제 값으로 치환 |
| **트리거 + 타이밍** | 이벤트(예약 확정/체크인 전/체크인 후/체크아웃 전/체크아웃 후) + 오프셋(N일) + 시각(HH:MM) |
| **자동 스케줄 생성** | 예약 확정 시 매칭 템플릿 → ScheduledMessage 인스턴스 자동 생성 |
| **Cron 자동 전송** | 주기적으로 대기 건 확인 → 시간 도래 시 메시지 전송 |
| **대화 내 타임라인** | 메시지 입력 옆 + 버튼 → 예약 메시지 목록 모달 (완료/대기/건너뜀) |
| **건너뛰기 / 지금 보내기** | 대기 건에 대한 수동 조작 |
| **한/일 다국어** | 모든 UI 문구 host-i18n 적용 |

## 3. 데이터 모델

### 3.1 Prisma 스키마

```prisma
// ---------- 예약 메시지 템플릿 (호스트가 생성·관리) ----------
model ScheduledMessageTemplate {
  id        String   @id @default(cuid())
  hostId    String
  host      User     @relation("HostTemplates", fields: [hostId], references: [id], onDelete: Cascade)

  title     String                // 관리용 제목: "(Shibuya) Check-in Guide"
  body      String                // 본문 (단축 코드 포함 가능)
  trigger   String                // "booking_confirmed" | "before_checkin" | "after_checkin" | "before_checkout" | "after_checkout"
  offsetDays Int     @default(0)  // 트리거 기준 오프셋 (일). 양수=후, 음수=전. 예: before_checkin + offsetDays=2 → 체크인 2일 전
  sendTime  String   @default("10:00") // 전송 시각 (HH:MM, 숙소 타임존 기준)
  
  // 적용 범위
  listingId String?               // null = 호스트의 전체 숙소에 적용
  listing   Listing? @relation(fields: [listingId], references: [id], onDelete: Cascade)

  enabled   Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  scheduledMessages ScheduledMessage[]

  @@index([hostId])
  @@index([listingId])
  @@index([hostId, enabled])
}

// ---------- 예약 메시지 인스턴스 (예약별로 자동 생성) ----------
model ScheduledMessage {
  id             String   @id @default(cuid())
  conversationId String
  conversation   Conversation @relation(fields: [conversationId], references: [id], onDelete: Cascade)
  templateId     String
  template       ScheduledMessageTemplate @relation(fields: [templateId], references: [id], onDelete: Cascade)

  // 전송 시각 (UTC로 저장, 생성 시 숙소 타임존에서 변환)
  scheduledAt    DateTime

  // 전송 시 단축 코드가 치환된 최종 본문 (생성 시점에 미리 렌더링)
  renderedBody   String

  status         String   @default("pending")  // "pending" | "sent" | "skipped"
  sentAt         DateTime?
  sentManually   Boolean  @default(false)       // true = "지금 보내기"로 전송
  messageId      String?  @unique               // 전송된 Message의 ID (sent 상태 시)
  createdAt      DateTime @default(now())

  @@index([conversationId])
  @@index([status, scheduledAt])
}
```

### 3.2 기존 모델에 추가할 relation

```prisma
// User 모델에 추가
model User {
  // ... 기존 필드 ...
  scheduledMessageTemplates ScheduledMessageTemplate[] @relation("HostTemplates")
}

// Listing 모델에 추가
model Listing {
  // ... 기존 필드 ...
  scheduledMessageTemplates ScheduledMessageTemplate[]
}

// Conversation 모델에 추가
model Conversation {
  // ... 기존 필드 ...
  scheduledMessages ScheduledMessage[]
}
```

## 4. 단축 코드 (Shortcodes)

### 4.1 지원 단축 코드

도쿄민박 DB에서 이미 보유한 데이터를 기반으로, 1차에서 지원할 단축 코드:

| 코드 | 치환 값 | 출처 |
|------|---------|------|
| `{guest_name}` | 게스트 이름 | `booking.user.name` |
| `{host_name}` | 호스트 이름 | `listing.user.name` |
| `{listing_name}` | 숙소 이름 | `listing.title` |
| `{listing_address}` | 숙소 주소 | `listing.location` |
| `{checkin_date}` | 체크인 날짜 (YYYY-MM-DD) | `booking.checkIn` |
| `{checkout_date}` | 체크아웃 날짜 (YYYY-MM-DD) | `booking.checkOut` |
| `{guests_count}` | 인원 수 | `booking.guests` |
| `{nights}` | 박수 | 계산: checkOut - checkIn |
| `{total_price}` | 총 금액 (포맷팅) | `booking.totalPrice` |
| `{booking_id}` | 예약 ID | `booking.id` |
| `{house_rules}` | 주의사항 | `listing.houseRules` |

### 4.2 렌더링 시점

- **ScheduledMessage 인스턴스 생성 시** `renderedBody`에 치환된 본문을 저장.
- 이유: 전송 시점에 예약·숙소 정보가 변경될 수 있으므로, 생성 시점의 스냅샷이 더 정확함.
- **지금 보내기** 시에도 `renderedBody`를 그대로 사용 (이미 렌더링됨).

## 5. 자동 스케줄 생성 로직

### 5.1 시점

**예약 확정(결제 완료) 시** — 기존 코드에서 `status: "confirmed"`, `paymentStatus: "paid"`로 갱신하는 곳:
- `POST /api/payments/verify` (결제 검증)
- `POST /api/webhooks/portone` (Portone 웹훅)
- `POST /api/cron/charge-deferred` (후불 결제)
- `POST /api/bookings` (즉시 예약 → 결제 완료까지)

### 5.2 로직

```
1. 예약 확정 시 → 해당 숙소의 호스트 ID 조회
2. ScheduledMessageTemplate에서 조건 조회:
   - hostId = 호스트 ID
   - enabled = true
   - listingId = null (전체) OR listingId = 해당 숙소 ID
3. 각 템플릿에 대해:
   a. scheduledAt 계산:
      - trigger=booking_confirmed → now + offsetDays일의 sendTime
      - trigger=before_checkin → checkIn - offsetDays일의 sendTime
      - trigger=after_checkin → checkIn + offsetDays일의 sendTime
      - trigger=before_checkout → checkOut - offsetDays일의 sendTime
      - trigger=after_checkout → checkOut + offsetDays일의 sendTime
   b. scheduledAt이 이미 과거면 건너뛰기 (생성하지 않음)
   c. 단축 코드 렌더링 → renderedBody 생성
   d. ScheduledMessage 레코드 생성 (status: "pending")
```

### 5.3 타임존

- 도쿄민박의 숙소는 모두 일본(Asia/Tokyo, UTC+9)이므로, sendTime을 JST로 해석 → UTC로 변환해 scheduledAt에 저장.
- Cron 비교는 UTC 기준.

## 6. API 설계

### 6.1 템플릿 관리 (호스트용)

| Method | Path | 설명 |
|--------|------|------|
| **GET** | `/api/host/scheduled-templates` | 내 템플릿 목록 (enabled 포함 전체) |
| **POST** | `/api/host/scheduled-templates` | 템플릿 생성 |
| **PATCH** | `/api/host/scheduled-templates/[id]` | 템플릿 수정 |
| **DELETE** | `/api/host/scheduled-templates/[id]` | 템플릿 삭제 |

**POST/PATCH body 예시:**
```json
{
  "title": "(Shinjuku) Check-in Guide",
  "body": "{guest_name}님, 체크인 안내입니다.\n\n주소: {listing_address}\n체크인: {checkin_date}\n하우스룰: {house_rules}",
  "trigger": "before_checkin",
  "offsetDays": 1,
  "sendTime": "15:00",
  "listingId": "clxxx...",
  "enabled": true
}
```

### 6.2 대화별 예약 메시지 (대화 참여자용)

| Method | Path | 설명 |
|--------|------|------|
| **GET** | `/api/conversations/[id]/scheduled-messages` | 이 대화의 예약 메시지 목록 (타임라인) |
| **POST** | `/api/conversations/[id]/scheduled-messages/[scheduleId]/send-now` | 지금 보내기 |
| **POST** | `/api/conversations/[id]/scheduled-messages/[scheduleId]/skip` | 건너뛰기 |

### 6.3 Cron (자동 전송)

| Method | Path | 설명 |
|--------|------|------|
| **POST** | `/api/cron/send-scheduled-messages` | pending && scheduledAt <= now 인 건 일괄 전송 |

## 7. Cron 자동 전송

### 7.1 실행 주기
- Vercel Cron: **10분마다** (또는 5분)
- `vercel.json`에 추가:
```json
{ "path": "/api/cron/send-scheduled-messages", "schedule": "*/10 * * * *" }
```

### 7.2 동작
```
1. ScheduledMessage WHERE status="pending" AND scheduledAt <= now() 조회 (limit 50)
2. 각 건에 대해:
   a. 해당 conversation의 호스트 userId 조회
   b. Message 생성 (senderId = 호스트, body = renderedBody)
   c. ScheduledMessage 갱신: status="sent", sentAt=now(), messageId=생성된 메시지 ID
   d. (선택) 게스트에게 알림/이메일 발송 (기존 새 메시지 알림 로직 재사용)
3. 실패 시 해당 건만 로그 남기고 다음 건 처리 (개별 try-catch)
```

## 13. 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 예약 취소 시 | 해당 conversation의 pending ScheduledMessage를 모두 skipped 처리 |
| 템플릿 삭제 시 | 이미 생성된 ScheduledMessage는 cascade 삭제 (pending이면 전송 안 됨) |
| 템플릿 비활성화 시 | 이미 생성된 pending 인스턴스는 그대로 유지 (새 예약에만 미적용). 또는 선택적으로 pending을 skipped 처리 |
| 동일 템플릿 중복 생성 방지 | conversationId + templateId unique constraint 추가 고려 |
| scheduledAt이 과거 | 스케줄 생성 시 이미 과거인 건은 생성하지 않음 |
| 체크인이 당일(즉시 예약) | "체크인 1일 전" 등이 이미 과거 → 생성 건너뜀. "예약 확정 시"만 생성됨 |
