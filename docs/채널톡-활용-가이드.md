# 도쿄민박 채널톡 활용 가이드

이 서비스(숙소 예약, 게스트/호스트, 결제·환불)에서 채널톡을 **가장 효과적으로** 쓰기 위한 설정·운영·기술 연동 정리.

---

## 1. 현재 상태

- **연동**: 전역 위젯 적용됨 (모든 페이지 우측 하단)
- **문의 진입점**: 채널톡 단일 (카톡문의·숙소 상세 문의 버튼 제거 완료)
- **미적용**: 사용자 식별(프로필), 언어 설정, ALF·태그 등

---

## 2. 효과를 높이는 활용 방향

### 2-1. 즉시 적용 (채널톡 관리자 + ALF)

| 항목 | 내용 |
|------|------|
| **ALF 지식** | 숙소 문의·예약·취소·환불 FAQ, 이용규칙, 체크인/아웃 안내를 문서로 정리해 ALF 지식에 등록. 1차 응답 자동화. |
| **ALF 규칙** | "한국어로 답변", "확실하지 않으면 상담원 연결", "환불·취소는 정책 문서 기준만 안내" 등 지시문 설정. |
| **상담 태그** | 문의 유형 태그 사용 (`숙소문의` / `예약문의` / `환불·취소` / `호스트문의` / `기타`) → 상담원이 우선순위·담당 구분. |
| **영업시간·자동메시지** | 영업시간 외 안내 + "채팅 남겨주시면 다음 날 답변드립니다" 등 자동 메시지로 기대감 관리. |

→ **효과**: 반복 문의 감소, 응답 일관성, 상담원 업무 구분 명확.

### 2-2. 단기 적용 (웹 설정)

| 항목 | 내용 |
|------|------|
| **위젯 언어** | boot 옵션 `language: 'ko'` 또는 `'ja'` 설정. 사이트 언어(한국어/일본어)에 맞추면 게스트가 더 잘 이해. |
| **로그인 사용자 프로필** | 로그인 시 채널톡에 `profile`(이름, 이메일) 전달. 상담원이 "누가 문의했는지" 바로 확인 가능. |
| **페이지별 컨텍스트** | (선택) 숙소 상세·예약 확인·결제 완료 등 페이지에 따라 `customData`로 현재 숙소 ID·예약 ID 전달 시, 상담원/ALF가 문의 맥락 파악에 유리. |

→ **효과**: 상담 품질·속도 향상, 중복 확인 감소.

### 2-3. 중기 적용 (운영·자동화)

| 항목 | 내용 |
|------|------|
| **예약/결제 후 안내** | "예약이 완료되었습니다. 궁금한 점은 우측 하단 채널톡으로 문의해 주세요" 등 한 줄 안내 (예: 예약 완료·결제 완료 페이지). |
| **예약·결제 확정 후 채널톡 알림** | 결제 확정 → 메시지창으로 이동 시, 서버에서 채널톡 Open API로 봇 메시지 발송 시 사용자가 위젯에서 확인 가능. (본 문서 4-2 참고) |
| **ALF 태스크** | 취소·환불 정책이 안정화되면 ALF v2 태스크로 "취소 요청" 시 우리 API와 연동해 자동 처리 검토. |
| **채널톡-내부 메시지 연동** | 사이트 내 메시지(호스트↔게스트)와 채널톡을 분리 유지하되, "예약 관련 문의는 채널톡, 숙소 상세·날짜 조율은 내부 메시지"처럼 역할을 정리해 고객에게 안내. |

→ **효과**: 문의 채널 혼동 감소, 반복 업무 자동화.

---

## 3. 도쿄민박에 특히 유리한 점

- **한국어 중심**: ALF 지식·규칙을 한국어로 통일하면, 주요 타깃(한국인 게스트) 1차 응답 품질이 올라감.
- **일본어 대응**: 일본어 이용자 비중이 있으면 ALF 규칙에 "일본어 문의 시 일본어로 답변" 추가, 또는 위젯 `language`를 페이지/사이트 언어에 맞춤.
- **문의 유형이 뚜렷함**: 숙소 문의 / 예약·결제 / 취소·환불 / 체크인·시설 → FAQ와 태그를 이 4가지로 정리하면 운영이 단순해짐.
- **단일 문의창**: 카톡·숙소 문의 버튼 제거로 "문의는 채널톡"만 안내하면, 고객과 상담원 모두 혼선이 줄어듦.

---

## 4. 메신저 창에서 로딩 표시가 사라지지 않을 때

메신저를 열었을 때 헤더 쪽 **빙글빙글 도는 로딩**이 끝까지 사라지지 않으면, 보통 **채널/회사 프로필(또는 헤더) 이미지**가 로드되지 않는 상태입니다.

**채널톡 데스크에서 확인할 것:**
1. [채널톡 데스크](https://desk.channel.io) → **설정** → **채널 설정** (또는 **프로필/브랜딩**)
2. **회사(채널) 프로필 사진**, **헤더/배경 이미지**가 등록되어 있는지 확인
3. 이미지 URL을 직접 넣었다면 **https** 주소인지, 브라우저에서 해당 URL을 열었을 때 이미지가 정상 보이는지 확인
4. 가능하면 이미지를 **채널톡 데스크에서 업로드**해 두면 `*.channel.io` 도메인으로 제공되어 CSP와 충돌하지 않음

사이트 측에서는 CSP에 `img-src`·`style-src`·`frame-src` 등에 채널톡 도메인(`*.channel.io`, `cdn.channel.io`, `cf.channel.io`)을 이미 허용해 두었습니다. 그래도 로딩이 계속되면 위 데스크 설정을 먼저 점검하세요.

## 5. 채널톡 버튼 위치 (모바일 하단 네비와 겹침 방지)

- 채널톡 플러그인은 **Shadow DOM**으로 렌더되어, 우리 문서의 CSS(예: `.circleChatButtonWrap`)가 **버튼 내부에 적용되지 않음**. 따라서 전역 CSS만으로 기본 버튼 위치를 바꿀 수 없음.
- **해결**: 기본 버튼을 숨기고(`hideChannelButtonOnBoot: true`), 우리가 렌더하는 **커스텀 런처 버튼**을 사용. 이 버튼의 위치를 모바일에서 `bottom: calc(4rem + 8px + safe-area)` 등으로 지정해 하단 네비 위에 두고, 클릭 시 `ChannelIO('showMessenger')` 호출.

## 5-2. 예약·결제 확정 후 채널톡으로 알림 보내기

**가능 여부**: 가능합니다. 채널톡 **Open API**로 서버에서 해당 사용자 채팅에 **봇 메시지**를 보내면, 사용자가 채널톡 위젯을 열었을 때 그 메시지가 보이고, 위젯 뱃지 등으로 알림 효과를 줄 수 있습니다.

**흐름 요약**

1. **부트 시 memberId 설정**  
   로그인 사용자에게 채널톡 boot 옵션에 `memberId: 우리_사용자_ID`(예: NextAuth session user id)를 넣어 두면, 채널톡이 그 사용자를 회사 측 사용자 ID로 식별합니다.
2. **결제 확정 처리 시점**  
   결제 확정 API(또는 결제 완료/예약 완료 처리하는 서버 로직) 안에서, 확정된 사용자 ID를 알고 있는 상태에서 다음을 수행합니다.
3. **채널톡 Open API 호출**  
   - `GET https://api.channel.io/open/v5/users/@{memberId}`  
     → 채널톡 User 조회 (memberId는 부트 시 넣은 우리 사용자 ID).
   - 해당 User의 **UserChat** 조회 또는 생성  
     - 조회: `GET .../user-chats` 등 (채널톡 문서의 UserChat 목록/생성 API 참고).  
     - 없으면 `POST https://api.channel.io/open/v5/users/{userId}/user-chats` 로 생성.
   - `POST https://api.channel.io/open/v5/user-chats/{userChatId}/messages`  
     → 요청 body에 봇 메시지 내용(예: "예약이 확정되었습니다. 메시지창에서 상세 내용을 확인하세요.")을 넣어 발송.

**필요한 것**

- 채널톡 **데스크** → 설정 → 보안 및 개발에서 **API 키(Access Key, Access Secret)** 발급.  
  → 서버 환경 변수에만 저장하고, 클라이언트에 노출하지 않습니다.
- 우리 서버(결제 확정/예약 완료 처리)에서 위 API를 호출할 수 있는 코드 추가.
- (선택) 부트 시 `memberId`를 우리 사용자 ID로 설정해 두면, API로 해당 사용자를 안정적으로 찾을 수 있습니다.

**알림이 “오는” 방식**

- **웹**: 사용자가 채널톡 위젯을 열면 해당 채팅에 봇 메시지가 보입니다. 뱃지 숫자 등은 채널톡 위젯 동작에 따릅니다.
- **모바일 앱(채널톡 SDK 연동 시)**: 푸시 알림은 FCM/APNs 설정이 추가로 필요하며, 채널톡 문서의 “푸시 알림” 절을 참고하면 됩니다.

**정리**: 예약·결제 확정 후 “메시지창으로 이동”하는 현재 플로우는 그대로 두고, **같은 시점에** 서버에서 채널톡 Open API로 봇 메시지를 한 통 보내면, 사용자가 채널톡을 열었을 때 알림처럼 확인할 수 있습니다.

## 6. 기술 연동 요약 (구현 시 참고)

- **boot 옵션**  
  - `pluginKey` (필수), `language` (권장), `profile` (로그인 시 권장), `customData` (선택).  
  - [채널톡 Boot 옵션](https://developers.channel.io/docs/web-boot-option) 참고.

- **로그인 사용자**  
  - boot 시점에 세션이 없을 수 있으므로, boot는 기본 옵션만 넣고, 세션 로드 후 `ChannelIO('updateUser', { profile: { name, email } })` 호출로 프로필 갱신.

- **ALF**  
  - 채널톡 관리자에서 ALF 설정. 지식(FAQ)·규칙만 잘 채워도 1차 응답에 큰 효과.

---

## 7. 우선순위 제안

1. **1순위**: ALF 지식 + 규칙 + 상담 태그 (관리자 설정만으로 효과 큼)
2. **2순위**: boot 시 `language` 설정, 로그인 시 `profile` 전달 (개발 소요 적음)
3. **3순위**: 예약/결제 완료 페이지에 채널톡 문의 안내 문구
4. **4순위**: 페이지별 `customData`, ALF 태스크(취소·환불 자동화)는 여유 있을 때 검토

이 순서로 적용하면 **최소 비용으로 채널톡 효과를 가장 크게** 낼 수 있습니다.
