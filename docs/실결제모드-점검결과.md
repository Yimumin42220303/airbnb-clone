# 실결제 모드 점검 결과

게스트가 신용카드 정보를 입력했을 때 **실제 트랜잭션**이 일어나도록 되어 있는지 프로덕트 전체를 점검한 결과입니다.

---

## 1. 결론 요약

| 항목 | 현재 상태 | 실결제 시 필요한 조치 |
|------|-----------|------------------------|
| **NEXT_PUBLIC_PORTONE_TEST_MODE** | `.env`에 `true` | **`false`로 변경** (또는 변수 제거) |
| **Vercel Production** | 점검 필요 | Production에 `NEXT_PUBLIC_PORTONE_TEST_MODE=false` 설정 또는 미설정 |
| **실제 결제 여부** | 포트원 채널 키에 따름 | `NEXT_PUBLIC_PORTONE_CHANNEL_KEY`가 **실연동** 채널 키인지 확인 |
| **모의 결제 버튼** | `ENABLE_MOCK_PAYMENT`로 제어 | Production에는 두 변수 **설정하지 않음** |
| **상단 배너 문구** | "테스트 결제만 가능합니다" 고정 | 실결제 시 문구 변경 또는 배너 비노출 권장 |

---

## 2. 상세 점검

### 2-1. 환경 변수 (로컬 `.env`)

- **NEXT_PUBLIC_PORTONE_TEST_MODE**
  - **역할**: 앱에서 “테스트 모드” 여부를 표시·메시지에 사용 (환불 실패 시 안내 문구 등).
  - **실결제 시**: `false`로 두거나 변수를 제거해야 합니다.  
  - **조치**: `.env`에서 `NEXT_PUBLIC_PORTONE_TEST_MODE=false` 로 변경함.

- **NEXT_PUBLIC_PORTONE_STORE_ID / NEXT_PUBLIC_PORTONE_CHANNEL_KEY**
  - 결제창이 어떤 **포트원 Store·채널**을 쓰는지는 여기서 결정됩니다.
  - **실제 트랜잭션** 여부는 포트원 콘솔에서 해당 채널이 **테스트연동**인지 **실연동**인지에 따라 결정됩니다.
  - **실결제**: `NEXT_PUBLIC_PORTONE_CHANNEL_KEY`에 **실연동** 채널의 Channel Key를 넣어야 합니다.

- **PORTONE_API_SECRET**
  - 결제 조회·환불 등 서버 API 호출에 사용. 실연동이면 포트원 API Keys의 **V2 Secret Key**와 동일해야 합니다.

- **ENABLE_MOCK_PAYMENT / NEXT_PUBLIC_ENABLE_MOCK_PAYMENT**
  - “테스트 결제 (모의 · 카드 없음)” 버튼 노출 여부. **Production에는 설정하지 않는 것**이 원칙입니다.

### 2-2. Vercel (배포 환경)

- **Production**에서 다음을 확인·설정하세요.
  - `NEXT_PUBLIC_PORTONE_STORE_ID` = 실연동 사용 Store ID  
  - `NEXT_PUBLIC_PORTONE_CHANNEL_KEY` = **실연동** 채널의 Channel Key  
  - `PORTONE_API_SECRET` = V2 Secret Key  
  - `NEXT_PUBLIC_PORTONE_TEST_MODE` = **설정하지 않음** 또는 **`false`** (실결제 시)  
  - `ENABLE_MOCK_PAYMENT`, `NEXT_PUBLIC_ENABLE_MOCK_PAYMENT` = **설정하지 않음**

### 2-3. 코드 동작

- **결제 요청**: `PayButton.tsx`에서 `PortOne.requestPayment()` 호출 시 `storeId`·`channelKey`를 사용.  
  → env에 넣은 Store ID·Channel Key에 해당하는 포트원 채널이 **실연동**이면 실제 결제가 발생합니다.
- **결제 검증**: `/api/payments/verify`에서 `getPayment(paymentId)`로 포트원에 조회 후 DB 반영.  
  → TEST_MODE와 무관하게, 포트원에 “실제 결제”로 들어온 건이면 그대로 확정 처리됩니다.
- **환불**: `NEXT_PUBLIC_PORTONE_TEST_MODE === "true"`일 때만 환불 실패 시 “테스트 모드” 안내 문구가 다르게 나갑니다.  
  → 실결제 환경에서는 TEST_MODE를 false로 두는 것이 맞습니다.

### 2-4. UI·문구

- **ProductStatusBanner**: 상단에 “프리-릴리스 버전입니다. 현재 테스트 결제만 가능합니다.” 문구가 노출됩니다.  
  → 실결제 서비스로 전환 시 문구 변경 또는 배너 비노출을 권장합니다 (`translations.ts`의 `guest.statusBanner` 수정 또는 컴포넌트에서 조건부 렌더링).

## 3. 실결제 체크리스트 (할 일)

1. **.env**  
   - [x] `NEXT_PUBLIC_PORTONE_TEST_MODE=false` 로 변경 (본 점검에서 반영함)
2. **Vercel Production**  
   - [ ] `NEXT_PUBLIC_PORTONE_TEST_MODE` 없음 또는 `false`  
   - [ ] `NEXT_PUBLIC_PORTONE_CHANNEL_KEY` = 실연동 채널 키  
   - [ ] `ENABLE_MOCK_PAYMENT`, `NEXT_PUBLIC_ENABLE_MOCK_PAYMENT` 미설정
3. **포트원 콘솔**  
   - [ ] 사용 중인 채널이 **실연동**인지 확인  
   - [ ] 결제 허용 URL에 운영 도메인 등록  
   - [ ] 웹훅 URL이 운영 도메인 `/api/webhooks/portone` 로 등록되어 있는지 확인
4. **문구**  
   - [ ] 실결제 전환 시 상단 배너 문구 변경 또는 비노출 여부 결정
